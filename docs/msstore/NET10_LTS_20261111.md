## 변경 내용과 실패를 해결한 근거

- `global.json`은 기존 설치 SDK10.0.403의 latestPatch를 선택한다. 앱·위젯·Interop·fixture 및 CI target은 net10.0으로 전환했다. `Otpeek.Core`의 netstandard2.1 표면은 유지한다. C#12, WinUI1.8, Windows SDK, Rust 코드/ABI, vault/backup/DPAPI 보호 계약은 바꾸지 않았다.
- 기존 Microsoft JSON/DI/Hosting/Drawing/ProtectedData 패키지를10.0.15로 맞췄다. 자체 포함 앱·위젯은10.0.15를 명시적으로 묶는다. 머신의10.0.14를 최종 shipping runtime으로 사용하지 않는다. [Microsoft 지원 표](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)에서 .NET10 LTS 지원 지속과 .NET8 종료를 확인했다.
- 최초의 전역 `RuntimeFrameworkVersion` 고정은 Windows SDK 참조에도 적용되어 NU1102를 냈다. `Directory.Build.targets`에서 `Microsoft.NETCore.App` FrameworkReference만 고정해 해결했다. Windows SDK 참조 버전을 런타임 버전으로 바꾸지 않는다.
- CS0012는 fixture가 .NET10 `Bitmap` 공개 표면의 `IImage`를 정의하는 DLL을 직접 참조하지 않아 생긴 컴파일 오류였다. `Otpeek.Windows.Fixtures.csproj`에 **실제 후보 payload의** `System.Private.Windows.GdiPlus.dll` 참조를 추가했다. 제품 QR 코드 변경 없이34 assertions를 통과했다.
- MSB3277은 ZXing0.16.17의 net10.0 DLL이 WPF용 `PresentationCore10`/`WindowsBase10`을 참조하지만 WinUI shell은 NETCore의 WindowsBase4 facade를 사용하는 데서 발생했다. 패키지 PE metadata를 읽어 netstandard2.0 DLL에는 `netstandard2`·`System.Drawing.Common10`·`zxing0.16.11`만 참조됨을 확인했다. **같은 패키지의 netstandard2.0 Bitmap binding을 명시적으로 선택**하고 기본 compile/runtime asset을 제외했다. 제외가 전이되면서 처음에는 ZXing core compile 참조가 사라져 CS0234/CS0246이 발생했고, 이미 쓰던 전이 의존성 ZXing.Net0.16.11을 직접 참조하여 해결했다. QR/OTP 알고리즘은 다시 구현하지 않았다. 최종 앱·위젯 빌드에서 MSB3277은0건이며 unpack한 shipping DLL 해시가 선택한 NuGet netstandard DLL과 일치한다.
- 패키지 verifier는 앱과 위젯 모두10.0.15 포함을 요구한다. 오래된8/9/10.0.14와 앱10/위젯8 혼합 후보를 거부하는 fixture를 추가했다.
