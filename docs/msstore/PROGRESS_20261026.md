# 출시 준비 진행 재확인 — 2026-10-26

완료된 Android 정책 회귀23개와 Windows 패키지 회귀15개를 반복하지 않고, 기존 미완료 항목의 진행 조건만 가볍게 재확인했다. 추가 저장소 AGENTS.md는 발견되지 않았고 기존 사용자 지침과 승인 범위를 유지했다.

## 완료 유지

- Android 수동/QR 등록, TOTP/HOTP, 암호화 저장·백업/복구와 기존 fixture 검증은 이전 기록을 따른다. 클립보드는 앱 전환 후 유지·30초 만료 시도·자기 항목만 정리하며 API26/35/36 관련23개 통과. OS 배경 제한/프로세스 종료 시 삭제 보장 한계도 안내되어 있다. [클립보드 QA](../android/CLIPBOARD_QA_20261025.md).
- Windows 자체 포함 .NET/runtime 고지와 배율 리소스 누락 수정, 최종4개 package 무결성, 격리 widget 내부 runtime 실행, 회귀15개 통과. WACK 선택58/88 및 DPI92의 SDK/도구 근거는 별도 보존했다. [최종 preview QA](SELF_CONTAINED_QA_20261025.md).

## 이번 실제 재확인과 미완료

- `ssh -o BatchMode=yes -o ConnectTimeout=8 jiun-home 'query session'`은 LAN `192.168.32.32:22` 연결 timeout으로 종료했다. 대화형 로그인 상태를 확인하거나 변경하지 못했다.
- 설치된 Tailscale CLI의 read-only 상태에서 `jiun-home`은 `Online=false`, `LastSeen=2026-10-25T17:20:00.1Z`였다. 이 값을 현재 로그인 사용자 판정으로 사용하지 않는다. 지금 새 Windows 앱 UI 검증을 재개할 수 있는 연결은 확보되지 않았다.
- 로컬 Store manifest는 여전히 `Otpeek / CN=Otpeek` placeholder다. 실제 Partner Center 식별자·계정 인증을 추측으로 대체하지 않았다. 제출·게시 없음.
- 새 self-contained fixture의 jiun 대화형 UI/runtime-module 확인, 실제 Store identity 연결/인증 후 최종 artifact 검증, Android 전용 실기기/OEM·운영 서명/계정별 출시 게이트는 남는다. 현재 기본 ADB5037 listener도 없었으며 장치 접근/서버 시작/설치는 하지 않았다.

기술 정책 선택은 기존 위임에 따라 처리되어 추가 선호도 답변을 기다리는 항목은 없다. 직접 인증·실제 식별자 및 실기기 확보는 필요하며 임의 계정/기기나 다른 프로젝트로 대신하지 않는다. Windows 연결이 복구되면 먼저 jiun 세션 상태를 확인한 뒤 남은 격리 UI 검사만 이어간다. 기존 통과 검증의 전체 재실행이나 새 운영 의존성/기능 구현은 하지 않았다.
