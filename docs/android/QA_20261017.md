## 발견해 수정한 제품 동작

- **파일 복구 취소:** 잠금 중 blocking 파일 읽기가 끝나면 기존 코드가 복구까지 계속할 수 있었다. 읽기 중/직후 및 master 해제 후 복구 직전에 coroutine 취소를 확인한다. fixture provider에서 읽기를 멈춘 뒤 잠금·재개하여 active pointer와 기존 계정이 유지되는지 검사했다. 내보내기도 Argon2/backup 생성 후와 chunk 쓰기 사이에 취소를 확인한다. 이미 외부 제공자가 쓴 부분 파일을 원격에서 지웠다고 보장하지는 않는다.
- **결과 메시지 유지:** TOTP의 1초 갱신이 백업/인증 결과 메시지까지 지웠다. 결과를 다음 작업까지 유지하며, export 후 1.3초가 지나도 성공 안내가 남는지 검증했다.
- **QR frame 방어:** byte buffer의 시작 position, row/pixel stride, 잘린/잘못된 프레임과 크기 상한을 처리했다. 해독 실패는 정상적인 “QR 없음”으로 다루고, 카메라 분석 예외는 수동 등록으로 돌아갈 수 있도록 처리한다. OTP URI/Google protobuf/crypto는 기존 Rust 그대로다.
- **작은 화면/큰 글꼴:** 잠금/생성 입력 화면에 스크롤과 IME 여백, 버튼/알고리즘 선택에 줄바꿈을 적용했다. 회전 후 미제출 비밀번호가 사라지는지, 기존 HOTP counter가 유지되는지 확인했다.
- **키 손실 안내:** 사라지거나 손상/무효화된 wrapping key를 일반 오류 대신 master password 복구 안내로 표시한다.
- **보관/복구 안내:** 삭제 계정은 기존 코어의 암호화 tombstone으로 남고 90일이 지난 뒤 다음 저장 시 제거되며 외부 백업은 남는다는 사실을 삭제 확인에 명시했다. 새 기기 복구도 오래된 HOTP counter를 재사용할 수 있음을 안내한다. 코어 계약을 바꾸거나 counter를 임의 보정하지 않았다.

## 초기 실패/진단의 구분

- test APK의 독립 provider 프로세스에는 target APK Kotlin stdlib가 포함되지 않아 초기 provider가 NoClassDefFoundError로 종료됐다. provider만 Java로 바꾸고 정상 suite를 다시 통과했다. 제품 dependency/crypto 변경은 없다.
- 작은 API30 화면과 200% 글꼴에서 기존 UI 테스트가 보이지 않는 LazyColumn/스크롤 영역을 클릭했다. 실제 스크롤 동작을 수행하도록 테스트를 수정해 통과했다. 생성 패널의 스크롤/줄바꿈 제품 수정은 별도로 위에 기록했다.
- 카메라 이미지 fixture가 에뮬레이터의 회전된 viewport에서 잘려 finder pattern을 잃었다. test-APK-only probe로 640×480 Y plane을 확인해 **공개 QR fixture의 배치**를 조정했다. OTP parser/인식 기준/화면 보안 플래그를 완화하지 않았다. 최종 probe는 decodedPublicFixture=true이며 실제 앱 UI도 통과했다.
- Android 권한 버튼은 문자열 대신 resource ID로 선택했고, probe가 남긴 fixture camera 권한은 카메라 QA 시작 전 revoke해 deny/regrant를 재현한다.
- 재부팅 자동화의 처음 시도는 boot_completed의 이전 값을 보거나 OS PIN 화면이 준비되기 전에 입력했다. boot ID 변경과 새 부팅 완료, 잠금 화면 준비를 구분하도록 보정했다. 초기 자동화 실패를 앱의 재부팅 성공으로 계산하지 않는다.
- 진단 runner를 생성하는 빌드와 다른 AVD의 테스트 APK 설치가 겹친 한 실행은 runner mismatch로 종료됐다. 고정된 default runner APK를 사용해 한국어/큰 글꼴을 다시 검증했다. 최종 전달용 test APK는 기본 AndroidJUnitRunner로 복구한다.

### 복사 정책 선택 대기

현재 승인된 정책은 Activity pause/stop 및 명시 잠금 시 앱 소유 OTP clipboard를 즉시 정리한다. 앱 전환 후 다른 앱에 붙여넣는 통상적인 OTP 사용을 막거나 OS별 cleanup 허용 시점에 따라 일관성 없게 만들 수 있다. vault/client의 background 즉시 잠금은 유지하면서 clipboard만 TOTP 만료 또는 최대30초/HOTP30초까지 유지할지 사용자에게 선택을 요청했다. 앱 프로세스 종료 시 예약 삭제는 보장할 수 없다는 한계도 함께 알렸다. **답변 전에는 이 보관 정책을 임의 변경하지 않는다.** 출시 전 선택 확정 및 다른 앱 붙여넣기 흐름 검증이 필요하다.

최종 정리: fixture AVD들은 검증 후 이 작업이 띄운 프로세스만 종료했다. 기본 runner suite를 마지막으로 다시 실행해 API35 12개를 통과했고, 전달용 test APK의 AndroidJUnitRunner도 확인했다. source XML/한국어·영어47개 resource, shell/Python syntax, whitespace/변경 경로/산출물 ignore를 검사했다. 기존 코어 product `.rs`/Cargo.lock과 Apple·Windows shell은 변경하지 않았다.
